# Attention — Triage the stale items that never resurfaced.

## Purpose

The deliberate triage ritual for the **Attention surface**: stale `carryover[]`, aging `backlog[]`,
and orphaned `/capture` notes that have aged past their `brain.toml [attention]` thresholds. These are
the "I'll get to it later" items that otherwise rot until you happen to `/prime` the one repo they live
in. This command brings them forward and forces a decision on each.

**Tier-aware.** Run at the HQ root, it triages the whole corpus. Run inside a tier (`cd core`), it
triages just that tier's board. The board itself is passive (regenerated by `mev emit-state` into every
`status.md`); this command is the active pass over it.

## When to use

- Periodically (e.g. weekly, or whenever `/prime` shows a crowded Attention section).
- After a burst of `/capture` / `/backlog-ticket` activity, to keep the queue honest.

## Steps

1. **Gather the live list.** From the current location (walk up to `brain.toml`):
   - Run `mev validate-brain --state` and collect every `W_STATE_CARRYOVER_STALE` /
     `W_STATE_BACKLOG_STALE` warning (each names the file, slug, kind, and age).
   - Cross-check the rendered `<!-- BEGIN generated:attention -->` region in the relevant `status.md`
     (HQ board at root; the current tier's board when inside a tier). The two must agree — if they
     don't, run `mev emit-state --write` first and re-read.
   - If the list is empty, say so and stop (nothing to triage).

2. **Present the queue**, oldest-first, grouped by lane (Stale carryover · Aging backlog · Orphaned
   captures), each row: `[repo] slug (kind/status, Nd) — gist` + its `clears_when` if any.

3. **For each item, pick one disposition** (ask the user per-item, or take a batch instruction like
   "snooze all the base-template ones, promote pt-br-mirror-pass"):

   | Disposition | What it means | How to apply |
   |---|---|---|
   | **Promote** | It's real work → give it a home | `/plan` · `/ticket` · `/chore` · `/generate-master-plan` (backlog → node gets `status:"promoted"` + `block`; carryover `deferred` → author the block, then **delete** the carryover entry) |
   | **Keep / re-affirm** | Still valid, looked at it, reset the clock | set `reviewed: <today>` on the entry (full threshold reset) |
   | **Snooze** | Real but not now | `/snooze <slug> [--days N]` (sets `snoozed_until`, default +3d) |
   | **Resolve / done** | `clears_when` is met, or it's obsolete | **delete** the `carryover[]` entry / mark the backlog node (superseded) |
   | **Archive / won't-do** | Not going to happen | delete the node and retire its `notes.md` via `/archive` (honors the D35 "never archive empty-handed" distill gate) |

   All authored-field edits go through the `/update-state` discipline (read
   [`docs/state/state-schema.md`](../../docs/state/state-schema.md); edit authored fields only;
   validate JSON). Never hand-edit derived fields.

4. **Regenerate + verify** once, after all dispositions:
   - `mev emit-state --write` — repaints every Attention board.
   - `mev validate-brain --state` — confirm the triaged warnings cleared and nothing new broke
     (`E_STATE_DATE_FORMAT`, dangling edges).

5. **Commit** the state.json + status.md changes with a conventional message (e.g.
   `chore: attention triage — promote X, snooze Y, resolve Z`). Then **report** a one-line summary per
   disposition.

## Notes

- The board shows exactly what the warnings fire on — same predicate, same thresholds (single source of
  truth in `mev`). If an item is on the board it is genuinely past threshold and un-snoozed.
- Prefer **promote** over endless **snooze**: snooze is a nap, not a home. An item you snooze three times
  probably wants a backlog node.
- Sibling commands: `/snooze` (quick nap) · `/backlog-ticket` · `/capture` · `/archive`.
